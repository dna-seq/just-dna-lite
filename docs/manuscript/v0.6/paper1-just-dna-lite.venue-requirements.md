# What the venues on this ladder ask for: iScience, Frontiers in Bioinformatics, JAMIA Open (Application Note), Cell Reports Methods, Genomics, PLOS Computational Biology (Software), NAR Genomics and Bioinformatics, Cell Genomics, bioRxiv and arXiv

Each requirement is listed with the venues that ask for it; "every venue" means all of them. A venue missing from an item may simply not have been researched for it (see the last section), which is not the same as having no rule.

## Adapt now: one version serves every venue

- Sections to add (one a single venue requires costs the others little):
  - [ ] Background and Significance (JAMIA Open (Application Note))
  - [ ] Data Availability Statement (JAMIA Open (Application Note))
- Rules the editors check on arrival, to check against the draft:
  - [ ] Studies involving humans name the approving committee in STAR Methods, or the committee that granted an exemption (iScience)
  - [ ] Sex or gender and age reported for human participants, or the reason they are not (iScience)
  - [ ] Consents, permissions and releases for personal information about any individual; nonessential identifying information omitted (iScience)
  - [ ] A structured data and code availability statement (data, code, additional information) in a Resource availability section (iScience)
  - [ ] AI tools that are part of the methods named with model or tool, version and developer in STAR Methods (iScience)
  - [ ] Written informed consent for publication of any potentially identifiable human data; the editors decide what is identifiable, and nonessential identifying details are omitted (Frontiers in Bioinformatics)
  - [ ] An ethics statement generated by the submission system; an exemption from approval is explained there, and a letter from the committee may be requested (Frontiers in Bioinformatics)
  - [ ] A data availability statement for every article, generated from the submission form (Frontiers in Bioinformatics)
  - [ ] An ethics statement that gives the review board's approval and number, or says that no approval was required (JAMIA Open (Application Note))
  - [ ] Identifying information only when essential, with written informed consent given after the person has seen the manuscript (JAMIA Open (Application Note))
  - [ ] A Data Availability Statement, with public datasets cited in the references with the [dataset] tag (JAMIA Open (Application Note))
  - [ ] Alt text under the legend of each figure (JAMIA Open (Application Note))
  - [ ] A manuscript already posted on another preprint server is not posted (so posting on arXiv first closes bioRxiv and medRxiv for it) (bioRxiv)
  - [ ] No narrative reviews (bioRxiv)
  - [ ] No announcements of tools or services without data (bioRxiv)
  - [ ] No hypotheses without new data (bioRxiv)
  - [ ] No editorials, letters, opinion pieces, white papers or policy statements (bioRxiv)
  - [ ] No images or information that could identify an individual, because consent cannot be verified; no stated exception for a person's own self-released data (bioRxiv)
  - [ ] At most 2 submissions per calendar month and 3 active per submitter; rejected ones count (arXiv)
  - [ ] CS review and position papers need a peer-reviewed version (journal ref and DOI) (arXiv)
  - [ ] A full English version is required (arXiv)
  - [ ] New submitters need an endorsement (institutional email alone no longer suffices) (arXiv)

## Choose per venue: the venues disagree

These wait until the venue is chosen, or follow the ladder's first choice.

- Length of the body: recorded limits are Frontiers in Bioinformatics, 12000; JAMIA Open (Application Note), 2000; Cell Reports Methods, 7000; PLOS Computational Biology (Software), 3500; Cell Genomics, 8000 words; other venues' limits are unknown. Keep this as a venue-specific choice until those rules are checked; no shared cap is established.
- Length of the abstract: recorded limits are JAMIA Open (Application Note), 150; Genomics, 250; PLOS Computational Biology (Software), 300 words; other venues' limits are unknown. Keep this as a venue-specific choice until those rules are checked; no shared cap is established.
- Abstract headings: recorded only for JAMIA Open (Application Note) (Objectives, Materials and Methods, Results, Discussion, Conclusion); the other venues' headings are unknown. Keep this as a venue-specific choice until those rules are checked.
- Rules that only some venues state; a section order, a format or a reference style waits for the choice:
  - No particular format for the first submission: a title, the authors and affiliations, a summary and enough experimental information to interpret the results (iScience)
  - A cover letter, seen only by the editors, that explains the background, the conceptual advance and the significance of the work, and a completed declaration of interests form (iScience)
  - A Technology and Code article in this order: Abstract, Introduction, Method (with the code description), Results (with examples of use and limitations), Discussion (with scalability and limitations) (Frontiers in Bioinformatics)
  - The project link, the operating system, the programming language and any restriction on non-academic use stated in the article (Frontiers in Bioinformatics)
  - The code placed online in a repository with a DOI or URI for retrieval (Frontiers in Bioinformatics)
  - A link to a publicly accessible code repository, and a Jupyter notebook with working code examples where one applies (JAMIA Open (Application Note))
  - The sections Introduction, Design and Implementation, Results, and Availability and Future Directions; the title names the software (PLOS Computational Biology (Software))
  - A cover letter that explains how the Software criteria are met (PLOS Computational Biology (Software))
- Not needed until after the first review:
  - A summary of one paragraph of at most 150 words, without novelty claims such as 'novel' or 'first' (iScience)
  - A limitations-of-the-study subsection within the Discussion, specific to the paper, and a Resource availability section with lead contact, materials availability, and data and code availability (iScience)

## At the end, once the code, data and results are final

Done earlier, these have to be done twice.

- Software and availability:
  - [ ] OSI-compliant source code (PLOS Computational Biology (Software))
  - [ ] Documentation (PLOS Computational Biology (Software))
  - [ ] Test data (PLOS Computational Biology (Software))
- Where the AI-use statement goes (one statement, placed everywhere a venue asks):
  - [ ] Titled declaration after Declaration of interests (published) (iScience, Cell Reports Methods and Cell Genomics)
  - [ ] Methods or STAR Methods when AI is part of the research design or methods (iScience, Cell Reports Methods and Cell Genomics)
  - [ ] Acknowledgments (Frontiers in Bioinformatics)
  - [ ] Methods if applicable (Frontiers in Bioinformatics)
  - [ ] Cover letter (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Acknowledgements (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Methods if integral (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Separate declaration section immediately before the references (published) (Genomics)
  - [ ] Methods (AI in the research process or to write or edit code) (Genomics)
  - [ ] Methods (PLOS Computational Biology (Software))
  - [ ] Acknowledgements or figure legend (PLOS Computational Biology (Software))
  - [ ] In the manuscript (bioRxiv)
  - [ ] As for other computational methods (bioRxiv)
  - [ ] In the work (arXiv)
  - [ ] As for other methodology (arXiv)
- What the AI-use statement states:
  - [ ] Tool (iScience, JAMIA Open (Application Note), Cell Reports Methods, Genomics, NAR Genomics and Bioinformatics and Cell Genomics)
  - [ ] Reason (iScience, Cell Reports Methods and Cell Genomics)
  - [ ] Model or tool + version + developer or manufacturer for research use and data visualizations (iScience, Cell Reports Methods and Cell Genomics)
  - [ ] Name (Frontiers in Bioinformatics)
  - [ ] Version (Frontiers in Bioinformatics, JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Model (Frontiers in Bioinformatics and Genomics)
  - [ ] Source (Frontiers in Bioinformatics)
  - [ ] How used (JAMIA Open (Application Note), PLOS Computational Biology (Software) and NAR Genomics and Bioinformatics)
  - [ ] Author oversight (JAMIA Open (Application Note), Genomics and NAR Genomics and Bioinformatics)
  - [ ] Dates (recommended) (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Sections (recommended) (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] Purpose (Genomics)
  - [ ] Extent (Genomics)
  - [ ] Tools (PLOS Computational Biology (Software))
  - [ ] What it affected (PLOS Computational Biology (Software))
  - [ ] How outputs were validated (PLOS Computational Biology (Software))
  - [ ] Use of generative AI tools (bioRxiv)
  - [ ] Significant use of text-to-text generative AI (arXiv)
- Extra work about AI:
  - [ ] Update the disclosure at every revision (JAMIA Open (Application Note) and NAR Genomics and Bioinformatics)
  - [ ] AI-written or AI-edited code declared in detail in Methods (Genomics)
  - [ ] AI-written code must be disclosed (PLOS Computational Biology (Software))

## AI writing rules on the list

- iScience: AI help is allowed if declared; only explicitly recorded exemptions apply.
- Frontiers in Bioinformatics: AI help is allowed, but every use must be declared, even language polish.
- JAMIA Open (Application Note): AI help is allowed if declared; only explicitly recorded exemptions apply.
- Cell Reports Methods: AI help is allowed if declared; only explicitly recorded exemptions apply.
- Genomics: AI help is allowed if declared; only explicitly recorded exemptions apply.

- NAR Genomics and Bioinformatics: AI help is allowed if declared; only explicitly recorded exemptions apply.
- Cell Genomics: AI help is allowed if declared; only explicitly recorded exemptions apply.
- bioRxiv: AI help is allowed if declared; only explicitly recorded exemptions apply.
- arXiv: AI help is allowed if declared; only explicitly recorded exemptions apply.

The strictest rule on the list is Frontiers in Bioinformatics's: AI help is allowed, but every use must be declared, even language polish. For the AI use you described, it means: allowed, but every use must be declared.
